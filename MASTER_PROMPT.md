Read `SKILL.md`, `DESIGN_SYSTEM.md`, `references/palette-presets.json`, `references/palette-engine.js`, `references/dark-glass-tokens.css`, `references/component-recipes.css`, the canonical demo/reference, and `ACCEPTANCE_CHECKLIST.md`.

Transform the user's existing interface, HTML, screenshot, module list or content requirements into a cohesive premium dark glass UI. Preserve the material DNA while allowing the selected palette to recolor the entire atmosphere: canvas, ambient light, glass tint, accents, highlights, data visualization and interaction states.

Do not treat teal-green as fixed. It is only one preset.

Use semantic tokens rather than scattered theme Hex values. Preserve the user's actual content and information architecture. The canonical three-region dashboard is a reference composition, not a mandatory shell.

When the user specifies a palette, use it. Otherwise select a restrained preset appropriate to the content. If the user provides five custom brand colors, map them into C1–C5 and derive semantic tokens before styling components.

For `US-11 blue-gold`, keep blue as the main material and use gold only as localized highlight, edge glow, stroke, sparkle or gradient endpoint.

Actually run the result in Chromium and capture screenshots before claiming visual consistency.
